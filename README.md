SS14 Studio is a visual companion for the files you already edit. It indexes a
Space Station 14 repository, renders construction graphs with real entity
sprites, resolves prototype inheritance and partial overlays, previews
RobustToolbox XAML with localized text and sprites, plays RSI animations, shows
C# namespace and partial context, and shows before/after diffs before it writes
anything.

The native text editor stays the default. SS14 Studio adds editor-title buttons,
code lenses, context-menu actions, an activity-bar tree, a status bar summary and
optional side-by-side previews. Nothing opens automatically unless you opt in.

## Construction graphs

- Browse every construction graph in the workspace from the **SS14 Studio**
  activity-bar view or the full dashboard.
- Inspect the whole graph on a blueprint canvas: nodes, directed step edges,
  conditions, materials, transforms, actions and completion steps.
- Entity sprites are resolved from prototype data and drawn on the nodes. Sheets
  are sent with crop metadata and cropped in the webview, so animated icons work.
- Search, filter and sort the graph atlas by folder, size or diagnostics.
- Follow incoming and outgoing paths, highlight a complete construction route,
  and inspect any node or edge in a focused panel.
- Edit through the YAML AST: add/delete nodes, connect and rename them, change
  entity prototypes, edit steps and step fields, add conditions, actions,
  transforms and completion actions. Comments and formatting survive.
- Create a new graph from a guided form.
- Every edit is a normal text edit, so VS Code's undo works as expected.
- Graph display is configurable: sprites, grid, entity ids, stats, edge steps,
  minimap, legend, controls, path highlighting, compact nodes, edge style and
  accent colors.
- Layout positions and zoom are stored in workspace state, not in the YAML.

## YAML prototypes

- Index every prototype under `Resources/Prototypes`, including Fluent locale
  names and partial-prototype manifests.
- Browse by kind, search by id, name or description, and jump to the YAML source.
- See the full parent tree and the direct children of a prototype.
- See resolved components and fields with their source, including inherited
  values, overridden values and which parent supplied them.
- Inspect active partial overlays and external partial effects. Partial
  directories declared in `Resources/PartialPrototypes/*.yml` (including the
  Starlight `/Prototypes/_Starlight/Partials` layout) are resolved.
- Understand RobustToolbox inheritance: multiple parents merge in order, child
  values override parents, and same-type components merge field by field.
- View an approximate in-game inspector card with sprite, name, description,
  price and key components. This is a data preview, not a running engine.
- Sprites are resolved through the whole inheritance chain. Compact `sprite:` /
  `state:` forms, direct textures and nested `layers:` are all understood, and
  every layer keeps its own path, state, colour, scale, offset and visibility.
- Create and edit a Sprite component, including multiple nested layers. The
  editor writes a complete override through the YAML AST and preserves unrelated
  Sprite fields.
- Inspect Storage and StorageFill visually: an approximate in-game grid shows
  item slots, footprints and overflow. Drag items to change spawn order, add or
  remove entities, and resize the grid; the generated YAML is previewed before it
  is written.
- Helper diagnostics flag component names ending in `Component`, PascalCase
  prototype or component keys that should be camelCase, and inherited components
  that are redeclared without overriding anything.
- Add and edit prototype fields and components from the inspector.
- Extract a YAML partial from selected fields and components, with a preview of
  the generated `!Partial:0` entry.
- Open an entity's RSI directly from its sprite preview.

## RobustToolbox XAML

- Parse XAML into an element tree and report structural problems, unknown
  controls, duplicate names, missing code-behind handlers and common SS14
  mistakes.
- Navigate from the outline and designer to the source line, and from the XAML
  root to its linked `.xaml.cs` file.
- Completion data for RobustToolbox controls, properties, namespaces and events.
- Approximate visual designer that renders containers, layout, text, styles and
  common control properties. It is intentionally labelled approximate.
- Resolve `{Loc key}` markup through the project's Fluent locale data, convert
  RobustToolbox colours and show RSI, texture and entity sprites in the designer
  instead of locale keys and raw paths.
- See the linked C# code-behind, its namespace, types, handlers and fields, and
  jump to the source line for missing or unused handlers.
- **Format XAML** and **Clean Up XAML** commands with a before/after diff. The
  file is only written after you review the change. Indentation defaults to four
  spaces and is configurable.
- **Mark XAML as AutoGenerated** adds the standard functional comment:
  `<!-- AutoGenerated by SS14 Studio. This file may be regenerated. -->`
  This is not an AI watermark, and it can be removed at any time.
- Diff view supports unified and split modes, line gutters, hunk headers and
  conflict-marker detection.

## C# context

- Open any `.cs` file in the **C# context** view from the command palette, the
  activity-bar sidebar, the editor-title menu or the editor context menu.
- See the file's namespace, usings, types, base types and partial declarations.
- Find other files that declare the same type (`partial` siblings), other types
  sharing the namespace, and the XAML files whose `x:Class` points at a type in
  this file.
- For `.xaml.cs` files, link back to the matching `.xaml`, list its controls and
  handlers, and flag a class that is not `partial` or a code-behind with no XAML.
- The scan is a lightweight, project-wide regex index, not a Roslyn workspace.
  It is cached until the next refresh, and it is intentionally conservative.

## RSI sprites

- Open any `meta.json` in an `.rsi` directory, or any RSI path, from the editor,
  explorer or command palette.
- Play animations with direction and frame controls, or step through frames.
- Inspect and edit states: directions, frame counts, per-frame delays, state
  names and metadata.
- Edit `license`, `copyright`, `version`, `size`, `metaAtlas` and `rsic`.
- Non-atlas RSI layouts are supported: state PNGs live beside `meta.json` and
  are shown directly.
- Import or replace a state PNG. New states get a generated transparent sheet.
- Basic RGBA pixel editor for quick fixes, with save support.
- Cleanup detects orphan PNGs and offers to remove them.
- `meta.json` writes are configurable: two-space indentation and a trailing
  newline by default, with both options exposed in Settings.
- Adding or removing frames updates `meta.json`; replace the PNG or use the
  pixel editor when the sheet itself must change.

## Diff and merge review

- Every text-changing XAML operation shows a before/after diff first.
- Unified and split layouts, added/removed counts, hunk headers and line numbers.
- Merge-conflict markers are detected and shown in a banner. SS14 Studio never
  applies a merge automatically: resolve the file in your editor, then reopen
  the comparison.
- Copy the new text from the diff view without applying it.

## Editor integration, not editor replacement

- **Native editors stay native.** The extension does not take over YAML or XAML
  by default.
- **Editor-title buttons** open the graph, prototype, RSI or XAML view for the
  current file.
- **Code lenses** above graphs, prototypes, XAML roots, code-behind files and RSI
  metadata.
- **Context menus** in the editor, explorer and view title bars.
- **Optional side preview** (`ss14Studio.autoSidePreview`) opens a read-only
  Studio view beside the file when you focus it, without stealing keyboard focus.
- **Opt-in default graph editor** (`ss14Studio.defaultGraphEditor`) opens the
  visual graph when you focus a construction-graph YAML file. The text file
  stays open.
- **Untrusted workspaces** run read-only.
- **Theme-aware** UI for light, dark and high-contrast themes.
- **No telemetry, no accounts, no hidden network calls.** The Rider sidecar
  binds to `127.0.0.1` only.

## Getting started

1. Open a Space Station 14 repository (one containing `Resources/Prototypes`).
2. Open the **SS14 Studio** activity-bar view, or run
   **SS14 Studio: Open Dashboard**.
3. Pick a construction graph, prototype, RSI or XAML file.
4. Explore. Nothing is written until you use an editing action, and XAML edits
   show a diff first.

Useful first steps:

- Open a graph and click a node to see its inspector.
- Open a prototype and switch between **Overview**, **Components**,
  **Inheritance** and **Partials**.
- Focus a `meta.json` inside an `.rsi` directory to open the RSI studio.
- Focus a `.xaml` file and run **SS14 Studio: Open XAML**.
- Focus a `.cs` file and run **SS14 Studio: Open C# Context for This File**.

## Architecture

The repository is a TypeScript monorepo plus a Kotlin Rider host:

```text
packages/core        Framework-agnostic parser, validator, AST editor,
                     inheritance resolver, storage/C#/RSI/XAML/diff models
                     and tests.
packages/ui          Shared React interface: React Flow graph canvas,
                     prototype/RSI/XAML studios, dashboard, diff, settings.
apps/vscode          VS Code extension host: indexer, webview panel,
                     code lenses, tree views, commands, packaging.
apps/rider           Kotlin plugin host + Node sidecar + JCEF bridge.
```

### How the hosts share the UI

- `packages/ui` talks to a small host bridge. In VS Code the bridge is
  `acquireVsCodeApi()`. In Rider the bridge is `window.ss14StudioBridge`, injected
  by the JCEF host before the UI bundle loads.
- The Rider sidecar indexes the project, serves the built UI over loopback HTTP,
  streams host messages with Server-Sent Events, and accepts UI messages over
  `POST /api/message`.
- The sidecar persists settings, layouts and UI state in a per-project state
  directory under the IDE system path. It performs `saveDocument` round-trips
  before writes and asks the Kotlin host to refresh/reload files afterwards.
- IDE actions (open file, notification, clipboard, file picker, settings, save,
  reveal) travel from the sidecar to Kotlin as JSON lines on stdout.

## Known limitations

SS14 Studio is alpha software and an AI-generated project. The full list lives
in [`AI-GENERATED.md`](./AI-GENERATED.md). The short version:

- The XAML designer and the prototype "in-game card" are approximate.
- Sequence-level `!Index` / `!CombineIndex` partial resolution is approximate.
- The C# index is a lightweight regex scan, not a compiler or Roslyn workspace.
- RSI frame add/remove updates metadata only; replace the PNG or use the pixel
  editor when the sheet changes.
- Diff views are read-only and never auto-merge.
- Rider runtime verification is pending on a local Rider installation.
- The first index of a large SS14 fork takes a few seconds.
