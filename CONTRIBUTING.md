# Contributing to SS14 Studio

Thanks for helping improve SS14 Studio. This is an AI-generated, human-reviewed
alpha project. Read the [AI disclosure](./AI-GENERATED.md) before contributing;
it explains the review policy, the no-watermark rule and the known limitations.

By participating, you agree to the [Code of Conduct](./CODE_OF_CONDUCT.md).
Security issues must follow [SECURITY.md](./SECURITY.md), not the public issue
tracker.

## Ways to help

- Report bugs with a minimal YAML, XAML or RSI reproduction.
- Test the VS Code extension and the packaged Rider plugin on real SS14 forks.
- Improve RobustToolbox coverage: construction step types, prototype inheritance
  edge cases, XAML controls, RSI metadata and partial-prototype semantics.
- Add tests, fixtures and documentation.
- Review AI-generated changes for correctness, not only for compilation.

Rider JCEF runtime testing is especially valuable. The Kotlin host builds and the
Node sidecar has an end-to-end smoke test, but the tool window has not been
verified on a local Rider installation in the development environment. See
[`apps/rider/README.md`](./apps/rider/README.md).

## Development setup

Requirements:

- Node.js 18 or newer (CI uses Node 20).
- npm 9 or newer.
- For the Rider plugin: JDK/JBR 21, Gradle 8.10.2 via the wrapper, and an
  internet connection for the IntelliJ Platform dependencies.

```bash
npm install
npm run check        # typecheck every workspace and run all test suites
npm run build        # core, shared UI and VS Code extension
npm run package      # VSIX in releases/
```

Useful scoped commands:

```bash
npm run test -w @ss14-studio/core
npm run test -w @ss14-studio/ui
npm run test -w @ss14-studio/rider-sidecar
npm run build:rider
node apps/rider/scripts/smoke.mjs
```

The smoke test defaults to the committed fixture at
`apps/rider/fixtures/sample-project`. Pass a real checkout path to test against
it:

```bash
node apps/rider/scripts/smoke.mjs C:\path\to\SS14\repo
```

### Rider plugin build

The Gradle build requires JDK 21. Point `JAVA_HOME` at a JDK 21 or Rider's
bundled JBR:

```powershell
$env:JAVA_HOME = "C:\path\to\jbr"
npm run build:rider
cd apps/rider
.\gradlew.bat buildPlugin --no-daemon
```

On Linux/macOS:

```bash
npm run build:rider
cd apps/rider
./gradlew buildPlugin --no-daemon
```

The ZIP is written to `apps/rider/build/distributions/`.

## Design rules

These rules are part of the product contract:

1. **Native editors stay the default.** Studio views open from explicit actions,
   opt-in settings or the tool window. Do not take over YAML or XAML globally.
2. **No silent writes.** Every text-changing operation previews a before/after
   diff, especially XAML formatting and cleanup.
3. **AST edits, not rewrites.** YAML prototype and construction-graph edits use
   source ranges and must preserve comments, ordering and formatting.
4. **No AI watermark.** The only generated-file marker is the functional
   `<!-- AutoGenerated by SS14 Studio. This file may be regenerated. -->`
   comment. Do not add AI badges or comments to user files.
5. **Approximate means labelled approximate.** The XAML designer and prototype
   in-game card are data previews, not engine renders.
6. **Loopback only.** The Rider sidecar binds to `127.0.0.1`, uses a per-launch
   token and does not send telemetry.
7. **Both hosts share the core and UI.** Put engine logic in `packages/core`,
   shared presentation logic in `packages/ui`, and keep host-specific code thin.

## Tests

- Add tests for parser, validator, editor, inheritance, RSI, XAML and diff
  behavior in `packages/core/test`.
- Add pure-logic UI tests in `packages/ui/test`.
- Add sidecar tests in `apps/rider/sidecar/test`; use temporary directories and
  the committed fixture instead of a real SS14 checkout.
- Keep tests deterministic and cross-platform (Windows and Linux run in CI).
- A bug fix should include a regression test when the behavior can be tested
  without a running IDE.

`npm run check` must pass before a pull request is ready for review.

## Pull requests

- Keep changes focused; split unrelated refactors.
- Describe user-visible behavior and include screenshots or recordings for UI
  changes.
- Update the README, command/setting tables and changelog when behavior changes.
- Complete the testing checklist in the pull request template.
- Call out AI assistance in the pull request and explain how it was reviewed.
- Do not commit generated build output (`releases/`, `dist/`, `apps/rider/web/`,
  `apps/rider/build/`) or secrets.

## Reporting bugs

Use the bug report form and include:

- SS14 Studio version from the About panel;
- VS Code or Rider version, and Node.js version for Rider;
- a minimal reproduction file or snippet;
- logs, stack traces or screenshots with private data removed;
- the SS14 fork and approximate repository size.
