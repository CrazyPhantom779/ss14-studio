**An all-in-one Space Station 14 development studio for VS Code:** construction
graphs with entity sprites, YAML prototype inheritance and partials, RobustToolbox
XAML tooling, RSI animation and pixel editing, C# context, and diff/merge review.

SS14 Studio is a visual companion, not an editor takeover. Your native YAML and
XAML editors remain the default. Studio views open from editor-title buttons,
code lenses, context menus, the activity bar or the command palette. Nothing
opens automatically unless you enable it.

## Features

### Construction graphs

- Browse every construction graph from the **SS14 Studio** activity-bar view or
  the dashboard graph atlas.
- A blueprint canvas with nodes, directed step edges, conditions, materials,
  transforms, actions and completion steps.
- Real entity sprites on nodes, including animated icons cropped from RSI state
  sheets.
- Search, filter and sort by folder, size or diagnostics.
- Follow incoming and outgoing paths and highlight a complete construction route.
- A focused inspector for nodes, edges, steps and completion actions.
- Surgical YAML editing: add/delete nodes, connect and rename them, change entity
  prototypes, edit steps and step fields, add conditions, actions and transforms.
  Comments, ordering and formatting are preserved, and normal undo works.
- Create a new graph from a guided form.
- Live diagnostics for missing targets, isolated nodes, unknown tags and malformed
  steps.
- Extensive display settings: sprites, grid, entity ids, stats, edge steps,
  minimap, legend, controls, path highlighting, compact nodes, edge style and
  accent colors.

### YAML prototypes

- Index prototypes under `Resources/Prototypes`, including Fluent locale names
  and partial-prototype manifests.
- Search by id, name or description and jump to the YAML source.
- Parent tree, direct children and inheritance chain.
- Resolved components and fields with their source, inherited values, overridden
  values and which parent supplied them.
- Active partial overlays and external partial effects, including Starlight's
  `/Prototypes/_Starlight/Partials` layout.
- RobustToolbox inheritance semantics: multiple parents merge in order, child
  values win, and same-type components merge field by field.
- An approximate in-game inspector card with sprite, name, description, price and
  key components.
- Sprites resolved through the inheritance chain, including compact, texture and
  nested `layers:` forms with per-layer colour, scale, offset and visibility.
- Create and edit Sprite components with multiple layers.
- Visual Storage and StorageFill editing: drag items to change spawn order, add
  or remove entities, resize the grid and preview the YAML before writing.
- Helper diagnostics for `Component` suffixes, PascalCase keys and redundant
  inherited components.
- Add and edit prototype fields and components.
- Extract selected fields and components into a YAML partial with a live preview.
- Open an entity's RSI directly from its sprite.

### RobustToolbox XAML

- Parse XAML and report structural problems, unknown controls, duplicate names,
  missing code-behind handlers and common SS14 mistakes.
- Outline, source navigation and linked `.xaml.cs` navigation.
- Completion data for RobustToolbox controls, properties, namespaces and events.
- Approximate visual designer for containers, layout, text, styles and common
  control properties, with resolved Fluent text, RobustToolbox colours and RSI,
  texture and entity sprites.
- Linked C# code-behind context: namespace, types, handlers, fields and source
  navigation.
- **Format XAML** and **Clean Up XAML** with a before/after diff before writing.
  Indentation defaults to four spaces and is configurable.
- **Mark XAML as AutoGenerated** adds the standard functional marker:
  `<!-- AutoGenerated by SS14 Studio. This file may be regenerated. -->`
  It is not an AI watermark and can be removed at any time.
- Diff view with unified and split modes, hunk headers, line gutters and
  conflict-marker detection.

### C# context

- Open any `.cs` file in the C# context view from the command palette, sidebar,
  editor-title menu or editor context menu.
- See namespaces, usings, type declarations, base types and partial modifiers.
- Find partial siblings, other types in the same namespace and XAML files whose
  `x:Class` points at a type in this file.
- For `.xaml.cs`, link back to the XAML, list controls and handlers, and flag a
  non-partial class or a code-behind with no matching XAML.
- The index is a cached, project-wide regex scan, not a Roslyn workspace.

### RSI sprites

- Open an RSI from `meta.json`, the command palette, the explorer or a prototype
  sprite link.
- Animated preview with play/pause, direction selection and frame stepping.
- Inspect and edit states, directions, frame counts, per-frame delays, names and
  metadata.
- Edit `license`, `copyright`, `version`, `size`, `metaAtlas` and `rsic`.
- Non-atlas layouts: state PNGs beside `meta.json` are shown directly.
- Import or replace a state PNG. New states get a generated transparent sheet.
- Basic RGBA pixel editor with save support.
- Cleanup detects orphan PNGs and offers removal.
- Configurable `meta.json` formatting: two-space indent and trailing newline by
  default.
- Adding or removing frames updates `meta.json`; replace the PNG or use the pixel
  editor when the sheet itself changes.

### Diff and merge review

- Before/after comparisons for XAML text operations.
- Unified and split views with added/removed counts and hunk headers.
- Merge-conflict markers are detected and shown in a banner.
- SS14 Studio never applies a merge automatically. Resolve the file in your
  editor, then reopen the comparison.
- Copy the new text without applying it.

### Editor integration

- **Native editors stay native.** No default takeover.
- Editor-title buttons for graphs, prototypes, XAML, C# and RSI.
- Code lenses above graphs, prototypes, XAML roots, code-behind files and RSI
  metadata.
- Editor, explorer and view-title context menus.
- Optional side preview (`ss14Studio.autoSidePreview`) opens a read-only view
  beside the focused file without stealing keyboard focus.
- Opt-in default graph editor (`ss14Studio.defaultGraphEditor`) opens the visual
  graph when you focus a construction-graph YAML file; the text file stays open.
- Read-only mode in untrusted workspaces.
- Light, dark and high-contrast themes.
- No telemetry, accounts or hidden network calls.

## Getting started

1. Install the extension and reload VS Code.
2. Open a Space Station 14 repository containing `Resources/Prototypes`.
3. Open the **SS14 Studio** activity-bar view, or run
   **SS14 Studio: Open Dashboard**.
4. Pick a graph, prototype, RSI, XAML or C# file and explore.

Nothing is written until you use an editing action, and XAML edits show a diff
first.

## AI disclosure and limitations

This extension is developed with AI coding agents and reviewed by humans. The
project is labelled here, in the repository README and in the in-app About panel.

Known limitations:

- The XAML designer and the prototype in-game card are approximate.
- Sequence-level `!Index` / `!CombineIndex` partial resolution is approximate.
- The C# index is a lightweight regex scan, not a compiler or Roslyn workspace.
- RSI frame add/remove updates metadata only; replace the PNG or use the pixel
  editor when the sheet changes.
- Diff views are read-only and never auto-merge.
- The first index of a large SS14 fork takes a few seconds.

Read the full [AI-generated disclosure](https://github.com/ss14studio/ss14-studio/blob/main/AI-GENERATED.md)
for scope, review policy and the no-watermark policy.
